# MQTT2API

[English version](https://github.com/alekslegkih/ha-addons/blob/main/mqtt2api/README_EN.md)

Аддон для **Home Assistant**, предоставляющий двунаправленный мост между MQTT
и HTTP API / WebSocket.

Предназначен для IoT-устройств: принимает данные из MQTT, отдаёт их внешним
клиентам по API и WebSocket, а также позволяет отправлять команды обратно
в MQTT.

## Возможности

- Двунаправленный обмен: MQTT ⇄ HTTP API / WebSocket
- Автоматическое подключение к брокеру Home Assistant через Supervisor
- Работа по TLS с использованием сертификатов из `/ssl`
- Подписка на топики `data`, `state`, `warnings` с фильтром по модулям
- Публикация команд в `<module>/<device_id>/cmd`
- Авторизация по Bearer-токену
- Потоковая передача событий через WebSocket

> [!NOTE]
> Аддон не хранит историю сообщений. WebSocket-клиент получает только те
> события, которые произошли после его подключения.

## Настройки

### API-секрет (`api_secret`)

Bearer-токен, который требуется для всех защищённых методов API и WebSocket.
Пример: `MU_SECRET`

### Модули (`modules`)

Белый список первых сегментов MQTT-топиков.
Пример: `["fridge", "relay"]`

> [!WARNING]
> Должен быть указан хотя бы один топик .

### TLS-сертификат (`certfile`)

Путь к TLS-сертификату в формате PEM внутри контейнера.
По умолчанию: `/ssl/fullchain.pem`

### TLS-ключ (`keyfile`)

Путь к приватному ключу TLS в формате PEM внутри контейнера.
По умолчанию: `/ssl/privkey.pem`

### Уровень логирования (`log_level`)

Допустимые значения: `debug`, `info`, `warning`, `error`, `fatal`, `off`.
По умолчанию: `warning`

## API

Аддон предоставляет HTTP API и WebSocket-интерфейс для внешних клиентов.
Авторизация — по Bearer-токену, который задаётся в настройках `api_secret`.

- **Состояние устройства** — текущие показания, статус и свежесть данных
- **Отправка команд** — публикация команды в MQTT-топик устройства
- **WebSocket** — поток событий в реальном времени: подключение к брокеру,
  новые данные, смена состояния, предупреждения
- **Health-check** — проверка работоспособности сервиса без авторизации

## Как это работает

Аддон подключается к брокеру MQTT через Supervisor API Home Assistant.  
После подключения к брокеру аддон подписывается на указаные в `modules` топики и транслирует
входящие сообщения во все активные WebSocket-соединения. HTTP-методы
`/api/state` и `/api/command` работают с тем же набором данных.

## Частые проблемы

- `modules is empty`:
    - Добавьте хотя бы один модуль в список `modules`

- `TLS file not found`
    - Укажите корректные пути в настройках `certfile` и `keyfile`
    - Проверьте что сертификат и ключ действительны

- `module_not_enabled` в ответе API
    - Запрошенный модуль не входит в список `modules` в настройках аддона
